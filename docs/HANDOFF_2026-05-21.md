## 1. TL;DR (so a new session can pick up cold)

The retrieval-evaluation pipeline runs end-to-end. Three team notebooks (`saul_base`, `saul_bm25`, `saul_sonar`) are shipped to GitHub, runnable on any teammate's fresh machine without fairseq2. A separate Colab notebook computes the paper-grade logprob baseline.

The empirical finding so far: **SaulLM-7B-Instruct collapses to predicting option "A" on ~80-90% of retrieval-augmented prompts.** This is intrinsic to the model under any K, prompt structure, or quant level we tested. Letter-emit numbers from `saul_bm25`/`saul_sonar` therefore mostly measure the A-bias, not retrieval quality. Logprob scoring (via llama-cpp-python in Colab) is the principled fix and matches the Zheng 2021 CaseHOLD eval protocol.

**Active blocker:** user is running the Colab logprob notebook on L4 GPU. When it finishes, it dumps `logprob_results.json` to Google Drive. Once that file is back in `notebooks/legal-rag/results/`, section 9 of each team notebook displays a letter-emit vs logprob comparison automatically.

## 2. What was done this session

### 2.1 Local pipeline brought up (2026-05-18)

The original `legal_rag_demo.ipynb` was failing on cell 3 because `fairseq2` could not locate `libsndfile`. Through several hours of debug we established:

1. **Stale venv.** The repo had moved from `lcm-research/` to `capstone-research/`. The `.venv` shebangs still pointed at the old path. Rebuilt at `notebooks/legal-rag/.venv/` with Python 3.12.8.
2. **CONDA_PREFIX trap.** `fairseq2n._load_sndfile()` checks `CONDA_PREFIX` and if set, skips the Homebrew lookup paths and only checks inside the venv lib tree. Because anaconda was on PATH, the conda branch fired even in a venv. Fix: symlinked `/opt/homebrew/lib/libsndfile.1.dylib` into `.venv/lib/libsndfile.1.dylib` (not `.venv/lib/python3.12/`).
3. **Jupyter kernel env.** Registered `legal-rag` kernel with `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib`, `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`, `TOKENIZERS_PARALLELISM=false`, `OMP_NUM_THREADS=1`, `MKL_NUM_THREADS=1`. Without OBJC fork-safety the SONAR encoder load segfaulted under ipykernel.
4. **faiss removed.** `faiss-cpu` + torch (via SONAR) double-load OpenMP on macOS arm64 and segfault on `faiss.search` after `sonar.predict`. `KMP_DUPLICATE_LIB_OK=TRUE` did not help. Replaced FAISS with numpy brute-force cosine (1.7 ms per query on 14,889 vectors, invisible next to Saul's ~5s/query).
5. **Cells 1-3 short-circuited.** `!pip install` and `subprocess.Popen(['ollama', 'serve'])` inside cells were leaving subprocess state that destabilized later cells. Replaced with idempotent state checks.

Result: notebook ran end-to-end on a 10-question sanity. First numbers were `bare=0.30, bm25=0.10, sonar=0.00`.

### 2.2 The A-bias diagnosis (2026-05-18)

Inspection of raw outputs showed 27 of 30 model responses were the single letter "A". Three probes confirmed:

| Probe | What | Result |
|---|---|---|
| `shuffle_probe.py` | Random-permute option labels per question | bm25 + sonar conditions: 100% "A" across all 10 questions. bare: varied. |
| `shuffle_probe_fix1.py` | K=5 to K=2 + 400-char truncation of retrieved docs | bm25/sonar: ~80% "A" (modest improvement). bare: unchanged. |
| `shuffle_probe_fix2.py` | Options-before-retrieval prompt structure | No additional improvement. |
| `shuffle_probe_q5.py` | Swap Q4_K_M for Q5_K_M quant | bare improves (acc 0.50 -> 0.60). Retrieval still ~80% "A". |

Conclusion: the bias is intrinsic to Saul-7B-Instruct under retrieval-augmented prompts, irrespective of K, prompt structure, or quant level. This is consistent with the SaulLM paper's own (Colombo 2024) Section 6.1 admission that Saul fails on conclusion tasks requiring deductive reasoning. The bias is itself a paper-worthy finding.

### 2.3 Logprob attempt locally (2026-05-18, failed)

Wrote `logprob_probe.py` to bypass letter emission. First version had two bugs (`logits_all=False` returned zero logits everywhere, broad except-clause masked retrieval errors). Fixed both. Then hit a deeper issue: in this Claude Code bash sandbox, `MTLCreateSystemDefaultDevice()` returns nil. Metal cannot initialize. Tried `n_gpu_layers=0`, `KMP_DUPLICATE_LIB_OK=TRUE`, rebuild with `-DGGML_METAL=OFF`, `LLAMA_NO_METAL=1` env. None worked because the Metal backend initializes unconditionally on macOS at runtime and the build flags did not propagate through pip's build isolation.

**Decision:** stopped chasing local logprob; moved it to Colab.

### 2.4 Pivot to Colab without fairseq2 (2026-05-19/20)

First attempt at a Colab notebook hit dependency hell: deprecated casehold loader script, then `transformers.PreTrainedModel` lazy-loader broke because of a torchvision circular import (torch 2.9.1+cu128 vs auto-pulled torchvision mismatch).

**Final pivot:** SONAR embeddings are deterministic. Precompute them once locally and ship as `.npy` files. The Colab notebook then needs zero of fairseq2 / sonar-space / transformers / torchvision.

Wrote `precompute_for_colab.py`. Ran it on the local venv (35 min on CPU). Outputs at `notebooks/legal-rag/data_for_colab/`:

- `sonar_corpus_2000.npy` (60 MB, 14,889 sentence vectors)
- `sonar_corpus_2000_meta.json` (sentence_to_parent map)
- `sonar_test_queries_50.npy` (200 KB, 50 query vectors)
- `manifest.json` (versions, shapes)

Committed and pushed. The user made the repo public so Colab can fetch via raw GitHub URL. The Colab notebook downloads these `.npy` files at startup, loads CaseHOLD CSV directly from HuggingFace, builds BM25 inline, scores logprob via llama-cpp-python CUDA wheel.

### 2.5 Team notebooks split (2026-05-20)

User specified the deliverable: three independent team-facing notebooks, one per retrieval condition. Generated via `_generate_team_notebooks.py`:

- `saul_base.ipynb` - bare Saul, no retrieval

All three share:

- Section 9: loads `results/logprob_results.json` if present and shows a side-by-side comparison

Wrote `notebooks/legal-rag/README.md` documenting setup, the A-bias finding, eval-method split (local letter-emit vs Colab logprob), and troubleshooting matrix.

### 2.6 CaseHOLD loader fix (2026-05-21)

`load_dataset('casehold/casehold', 'all')` fails on `datasets >= 4.0` because loader scripts were deprecated. The local notebooks worked only because the dataset was cached from May 13. Patched all four notebooks plus `precompute_for_colab.py` to use `load_dataset('csv', data_files=...)` against the canonical CSVs at `huggingface.co/datasets/casehold/casehold/resolve/main/data/all/`, with a column-rename matching the upstream `casehold.py` schema (column 0=example_id, 1=citing_prompt, 2-6=holding_0..4, 12=label).

Teammates on fresh installs now succeed without any datasets version pin.

### 2.7 Colab notebook made disconnect-safe (2026-05-21)

Added a Drive-mount cell. The eval output writes to `/content/drive/MyDrive/lcm-capstone/logprob_results.json` instead of just ephemeral `/content/`. `files.download()` is now best-effort and silently skips when the browser tab is closed. Pattern: open Colab on L4, Run All, close laptop, retrieve JSON from Drive later.
